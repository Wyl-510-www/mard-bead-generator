# 实现说明

## 数据流与职责

1. 首页在小程序端读取图片，使用离屏 Canvas 将图片等比缩放并合成白底，以目标两倍尺寸采样后平均缩图。
2. 将 RGB 像素编码为 Base64 调用 `generateBeadPattern`，不将原始图片写入云存储。
3. 云函数先检查尺寸、编码与字节长度，然后分批读取 `mard-colors`，交由纯函数 `generatePattern` 处理。
4. 算法将 sRGB 转为 D65 CIELAB，通过 Delta E 76 选择最近色号；限色模式使用加权主色聚类选出候选色卡，再匹配像素。照片模式可开启 Floyd–Steinberg 抖动。
5. 结果页管理网格编辑、撤销与重做、色号统计和预览；最近一份图纸写入本机缓存。PNG 通过 Canvas 导出，PDF 使用本地矢量指令生成。

## 关键取舍

- 真实色卡作为可制作颜色集合，避免生成现实中不存在的色号。匹配效果依赖色卡准确性，屏幕颜色与实物颜色可能有差异。
- 限色聚类中心会映射回真实色卡并去重，因此最终用色可能少于指定上限。
- 图片像素在客户端降采样后发送，减少传输量；100×100 图纸的原始 RGB 数据为 30,000 字节，Base64 为 40,000 字符，不含请求封装。
- 预览输出为图片，以便滚动与点击定位；异步预览回调校验请求次序，避免旧结果覆盖新结果。
- PNG 受最长边 4096 和总像素 400 万双重限制；PDF 保留矢量图形，但内置字体仅支持 ASCII 标签。
- 尺寸限制为 5–100；未对更大尺寸或大量并发请求作性能承诺。

## 测试边界

使用 Node.js 内置测试框架，覆盖算法、云函数入口、编辑、草稿、预览竞态、导出及包体规则。页面测试通过受控微信 API 替身运行，不等于微信真机、线上云函数或平台审核验收。完整生产色库没有随仓库发布。
